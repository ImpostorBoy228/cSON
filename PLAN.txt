# PLAN: генератор SONEVAL.ass + макрос cSON_evalpoint()

## 1. Цель

Из `.son`-файла генерировать C-файл `SONEVAL.ass`, содержащий макрос
`cSON_evalpoint()`. При вызове из C-кода (где в скоупе лежат переменные вроде
`owo`) макрос:
1. лениво парсит исходный `.son` в статическую переменную дерева
   (макросы `#define` уже применены на этапе `cSON_parse`);
2. для каждого IF-узла вычисляет условие как настоящее C-выражение прямо в
   скоупе вызывающего (поэтому `owo` виден);
3. разворачивает истинные IF-узлы в родителя или удаляет ложные.

Файл называется `SONEVAL.ass` (не `.h`) — имя может быть любым, препроцессор
не смотрит на расширение.

## 2. Контракт формата условия

Выражение внутри `!""` вставляется в генерируемый код **вербатим, без всякого
экранирования** (решение принято). Поэтому выражение должно быть полным
заголовком C-блока вида `if(<условие>)`. Пример:

```son
!"if(owo == "VAR")": {
    "text": "Hello owo!!"
}
```

резолвится в дерево как значение `if(owo == "dick")` (макрос VAR применён в
`cSON_parse`, cSON.h:245), а в сгенерированный код попадает дословно:

```c
if(owo == "dick") {
    cSON_apply_if(_son_root, 0, 1);
} else {
    cSON_apply_if(_son_root, 0, 0);
}
```

Если выражение НЕ начинается с `if(` — генерируется некорректный C
(`owo == "dick" { ... }`). Это задокументированное ограничение: выражение
обязано открывать C-блок.

## 3. Формат генерируемого файла

Для `emmm.son` (единственное IF-условие `if(owo == "dick")`):

```c
#ifndef SONEVAL_ASS
#define SONEVAL_ASS

#define cSON_evalpoint() ({ \
    static cSON_Obj* _son_root = NULL; \
    if (!_son_root) cSON_parse(&_son_root, "emmm.son"); \
    if(owo == "dick") { \
        cSON_apply_if(_son_root, 0, 1); \
    } else { \
        cSON_apply_if(_son_root, 0, 0); \
    } \
    _son_root; \
})

#endif /* SONEVAL_ASS */
```

Правила:
- include-guard от имени выходного файла (`SONEVAL_ASS`);
- `#define cSON_evalpoint() ({ ... })` — GNU statement expression
  (поддерживается cc/clang; проект уже собирается со `-std=c23`);
- статическая переменная `_son_root` — дерево парсится ровно один раз;
- блоки IF перечисляются **в обратном порядке документного обхода**
  (последний — первым), чтобы индексы узлов не смещались при изменении дерева;
- последним выражением макроса является `_son_root;` — макрос возвращает дерево;
- cSON.h **не подключается** из SONEVAL.ass — юзер обязан `#include "cSON.h"`
  сам, макросы `#define` из `.son` не дублируются.

## 4. Новые функции в src/cSON.h

### 4.1. `void cSON_apply_if(cSON_Obj* root, int index, int value)`

Generic-помощник, работает с любым деревом (не зависит от генератора).

Алгоритм:
1. Пройти дерево преордером (по `child`/`next`), считая CSON_IF-узлы, и найти
   узел с номером `index`.
2. Если узел не найден — no-op.
3. Если `value != 0` (условие истинно) — **развернуть в родителя**:
   - у IF-узла `c` есть child-объект `body` (то, что в `{...}`);
   - вынуть `c` из списка `parent->child`;
   - вставить детей `body` в список родителя на место `c`;
   - поправить `parent` у переехавших узлов;
   - освободить `body` и сам IF-узел (не трогая переехавших детей).
4. Если `value == 0` (ложно) — **удалить поддерево**: вынуть `c` из списка
   родителя и вызвать `cSON_free(c)` целиком.

Внутренний хелпер поиска по индексу:
```c
static cSON_Obj* cSON_if_by_index(cSON_Obj* o, int* counter, int target) {
    if (!o) return NULL;
    for (cSON_Obj* c = o->child; c; c = c->next) {
        if (c->type == CSON_IF) {
            if (*counter == target) return c;
            (*counter)++;
        }
        if (c->child) {
            cSON_Obj* f = cSON_if_by_index(c->child, counter, target);
            if (f) return f;
        }
    }
    return NULL;
}
```

### 4.2. `int cSON_gen_evalpoint(const char* out_path, const char* son_path)`

Публичное API (объявление вверху заголовка, реализация в impl-секции).

Алгоритм:
1. `cSON_parse(&root, son_path)`; если парс не удался или `root == NULL` —
   вернуть 0.
2. Собрать список пар `(index, value)` всех IF-узлов в порядке документного
   обхода. `value` уже макро-резолвнут (`cSON_resolve_all`).
   Хелпер сбора (накапливает в динамический массив структур).
3. Открыть `out_path` на запись. Писать:
   - include-guard;
   - строку с `#define cSON_evalpoint() ({ \`;
   - `static cSON_Obj* _son_root = NULL;` и ленивую инициализацию через
     `cSON_parse(&_son_root, "<son_path>")` (путь эскейпится как обычный
     C-string: `"` → `\"`, `\` → `\\`);
   - для каждого IF-узла в ОБРАТНОМ порядке:
     ```
     <value> { \
         cSON_apply_if(_son_root, <index>, 1); \
     } else { \
         cSON_apply_if(_son_root, <index>, 0); \
     } \
     ```
     `<value>` — дословно, без экранирования (контракт из п.2);
   - `_son_root; \`;
   - закрыть макрос `})` и guard.
4. `cSON_free(root)`; вернуть 1.

Особенности:
- `value == NULL` у IF-узла — подставить `0` в код (защита от краша);
- дубликаты условий НЕ дедуплицируются: каждый IF-узел обрабатывается по
  своему индексу;
- если IF-узлов нет — макрос просто парсит и возвращает дерево;
- вложенные IF раскрываются только повторными вызовами `cSON_evalpoint()`
  (один проход за вызов).

## 5. Изменения в src/cSON.c (CLI)

Добавить флаг `--gen-evalpoint`:

```
cSON --gen-evalpoint <out> <file.son>
```

Парсинг аргументов в `main`:
- `argc >= 4 && strcmp(argv[1], "--gen-evalpoint") == 0` →
  вызвать `cSON_gen_evalpoint(argv[2], argv[3])`, вернуть 0/1;
- иначе — прежнее поведение (dump `argv[1]`).

## 6. Тесты (tests/test.c)

### 6.1. `cSON_apply_if` — разворачивание (value=1)
Фикстура с IF-узлом:
```
{ "a": { !"if(x == 1)": { "b": "v" } } }
```
Парсим, вызываем `cSON_apply_if(root, 0, 1)`. Проверяем:
- у узла `a` больше нет child с типом CSON_IF;
- `cSON_get(a, "b")` возвращает `"v"` (дети переехали в `a`).

### 6.2. `cSON_apply_if` — удаление (value=0)
Та же фикстура, `cSON_apply_if(root, 0, 0)`. Проверяем:
- у `a` нет IF-узла и нет `b`.

### 6.3. `cSON_apply_if` — индекс вне диапазона
`cSON_apply_if(root, 99, 1)` — no-op, дерево не меняется.

### 6.4. `cSON_gen_evalpoint`
Фикстура `#define VAR dick` + одно IF-условие. Генерим в temp-файл.
Читаем его, проверяем подстроки:
- `#define cSON_evalpoint()`
- `if(owo == "dick")` (условие вставлено, макрос резолвнут)
- `cSON_apply_if(_son_root, 0, 1)`
- путь к фикстуре в `cSON_parse`.

## 8. Известные ограничения / решения

- Файл называется `SONEVAL.ass` — расширение не влияет на препроцессор,
  но редактор не будет подсвечивать синтаксис.
- Выражение в `!""` обязано быть полным заголовком C-блока (`if(...)`),
  иначе сгенерированный код не скомпилируется.
- Экранирование внутри IF-выражений не поддерживается и не требуется.
- `cSON_evalpoint()` — одноразовый проход: после разворачивания IF-узел
  исчезает из дерева; повторное пересчитывание требует пере-парсинга.
- Порядок обработки — обратный документному, чтобы индексы не сбивались.
